## Overview

FetchBrain can optionally collect diagnostics about how your requests
perform — timing, status codes, proxy outcomes, block indicators. It is
**off by default** everywhere in the SDK, and nothing is collected or sent
unless you opt in.

<Note>
  The SDK README's [Telemetry section](https://github.com/fetchbrain-com/sdk#telemetry-opt-in)
  is the disclosure of record: it lists every field, when each is sent, and
  [everything else that leaves your process](https://github.com/fetchbrain-com/sdk#what-leaves-your-process).
  This page summarizes it.
</Note>

## Enabling it

```typescript
FetchBrain.enhance(crawler, {
  apiKey: process.env.FETCHBRAIN_API_KEY,
  telemetry: { enabled: true }, // opt in — off by default
});
```

Every client path in the SDK — `FetchBrain.enhance()`, the standalone
`FetchBrain` class, and `FetchBrainClient` — is consistent: no `telemetry`
config means no telemetry.

## Pseudonymous, not anonymous

Telemetry is sent to the FetchBrain API with your API key and the SDK's
usual `X-FB-*` headers, so it is **linked to your account**. It's used to
improve FetchBrain's recommendations (proxy recommendations, block
detection, configuration tuning); aggregated statistics may inform
recommendations for other users.

## What gets collected

One entry per request FetchBrain handles (`skipLabels` requests excluded),
after your handler finishes — or whenever the request fails inside the SDK's
wrapper, including failures before your handler runs and on known requests.
Known requests that are skipped successfully produce no entry. Session,
proxy, status code and response size are sent only on success; a failure
entry carries `blocked: true`.

- **Always, when enabled:** the hostname in plain text (`domain`); the first
  16 hex characters of an **unsalted** SHA-256 of the full URL including its
  query string (`urlHash`); the path with numeric segments, UUIDs and
  20+ character alphanumeric tokens replaced by `*` — other segments such as
  slugs and usernames are sent as-is (`urlPattern`); `timestamp`;
  `crawlerType`; your `requestLabel`; and, if the request has a Crawlee
  session, its usage count and error score (on success).
- **`sharePerformance`:** retry count, timing from when the SDK starts
  handling the request (including recall), and on success the status code
  and response size.
- **`shareSitePatterns`:** `blocked` / `blockType`, derived from status codes
  (403, 429, 5xx) and error categories (`captcha`, `timeout`, `blocked`,
  rate limit). A request that fails inside the SDK wrapper for any reason
  counts as blocked.
- **`shareProxyInfo`** (on success): proxy country code, a proxy type guessed locally
  from the proxy URL, and whether the status was below 400.

Never sent by telemetry: raw URLs or query strings, request or response
bodies, your scraped requests' headers or cookies, error messages, or proxy
URLs and IPs.

## Sub-flags

Each sub-flag defaults to `true` once telemetry is enabled:

```typescript
FetchBrain.enhance(crawler, {
  apiKey: process.env.FETCHBRAIN_API_KEY,
  telemetry: {
    enabled: true,
    sharePerformance: true, // default: true
    shareProxyInfo: false, // default: true
    shareSitePatterns: true, // default: true
  },
});
```

<ParamField body="enabled" type="boolean" required>
  Master switch. `false` or omitted means no telemetry at all.
</ParamField>

<ParamField body="sharePerformance" type="boolean" default="true">
  Status codes, retry counts, timing, content size.
</ParamField>

<ParamField body="shareProxyInfo" type="boolean" default="true">
  Proxy country, locally-derived proxy type, and success. Never proxy URLs or IPs.
</ParamField>

<ParamField body="shareSitePatterns" type="boolean" default="true">
  Block indicators (`blocked`, `blockType`).
</ParamField>

## How collection behaves

- **Buffered and batched.** Entries are sent every 50 entries, every 30
  seconds, and when the crawl finishes.
- **Best-effort.** Send failures are ignored — they never throw into your
  crawl and never affect recall or learn.
