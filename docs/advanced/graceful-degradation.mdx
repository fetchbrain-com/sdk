## Overview

FetchBrain includes a built-in circuit breaker that ensures your scraper continues even if the FetchBrain API is unavailable.

## How It Works

```
API Healthy       → Normal operation, recall/learn active
API Slow (>500ms) → Timeout, continue without recall
API Down          → Circuit opens, scraper runs standalone
API Recovers      → Circuit closes, recall/learn resume
```

<Note>
  Your scraper will **never fail** due to FetchBrain issues. The SDK is designed
  for production reliability.
</Note>

## States

| State         | Behavior                                         |
| ------------- | ------------------------------------------------ |
| **Closed**    | Normal operation, all requests go through recall |
| **Open**      | Circuit tripped, bypass recall, run scraper directly |
| **Half-Open** | Testing if API recovered, partial requests       |

## Timeout Configuration

```typescript
const crawler = FetchBrain.enhance(crawler, {
  apiKey: process.env.FETCHBRAIN_API_KEY,
  timeout: 500, // ms, default
});
```

If FetchBrain doesn't respond within the timeout, the SDK:

1. Skips the recall for this request
2. Runs your handler normally
3. Increments the failure counter

After 3 consecutive failures, the circuit opens.

## Circuit Breaker Settings

The default circuit breaker:

- Opens after **3** consecutive failures (`failureThreshold`)
- Stays open for **30 seconds** (`resetTimeout`)
- Closes after **1** successful probe in half-open state (`successThreshold`)

You can override these via the `circuitBreaker` option:

```typescript
const crawler = FetchBrain.enhance(crawler, {
  apiKey: process.env.FETCHBRAIN_API_KEY,
  circuitBreaker: {
    failureThreshold: 5,
    resetTimeout: 60000,
    successThreshold: 2,
  },
});
```

## Monitoring

Enable debug logging to see circuit state:

```typescript
const crawler = FetchBrain.enhance(crawler, {
  debug: true,
});

// Logs:
// [FetchBrain] Circuit OPEN - bypassing recall
// [FetchBrain] Circuit HALF-OPEN - testing...
// [FetchBrain] Circuit CLOSED - recall online
```

## Best Practices

1. **Always set a timeout** - The default 500ms is good for most cases
2. **Use learning mode** - Even when circuit is open, requests are queued for learning
3. **Monitor stats** - Check `stats()` for recall rates
4. **Log errors** - Enable debug mode in staging to catch issues early
