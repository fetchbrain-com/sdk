# Welcome to FetchBrain

Every scraping run re-fetches requests you already made last time — paying
for proxies, browsers, retries, and CAPTCHAs to re-learn things you already
know. FetchBrain gives your scrapers a **shared memory pool**: known
requests come back in milliseconds with zero HTTP traffic; unknown ones run
normally and teach the brain for next time.

## The two-half model

FetchBrain is two capabilities working together:

<CardGroup cols={2}>
  <Card title="Memory" icon="database">
    **Recall** and **learn**. Before each request, the SDK asks "do I
    already know this?" Known requests skip the network entirely. Unknown
    ones run your handler, then teach the brain — automatically, and always
    free.
  </Card>
  <Card title="Intelligence" icon="sparkles">
    **Ask.** Once your scrapers have taught the brain enough, `ask()` runs a
    natural-language question across **everything** learned under your key
    — no exact URL, no warehouse, no second pipeline.
  </Card>
</CardGroup>

Memory is what makes repeat runs cheap. Intelligence is what makes the
accumulated data useful for more than the one scraper that collected it.

## How it works

```
Your crawler ──▶ FetchBrain ──▶ knows this request? ──▶ YES ──▶ data back, no fetch
                                      │
                                      └──▶ NO ──▶ your handler runs ──▶ brain learns, free
```

1. **Recall** — before each request, the SDK asks the brain if it already knows it
2. **Known** — data returns instantly and the HTTP request is skipped
3. **Learning** — unknown requests run through your handler as normal, and the result teaches the brain for every future run

This works for **any request, not just pages** — HTML, JSON APIs, POSTs with
bodies. Identity is derived from the full request server-side, so it isn't
limited to GET-and-a-URL scraping.

## Why a shared pool

Everything your scrapers learn accumulates under one API key — not one
scraper, not one run. Your daily product crawl, your price monitor, and your
side-project spider all deposit into the same brain. That compounding has
two payoffs:

- **Cost falls as coverage grows.** The more you've already taught the
  brain, the fewer requests need a real fetch on the next run.
- **`ask()` sees across all of it.** A question like "which products are
  under $20?" doesn't care which scraper originally learned that price —
  it searches the whole pool.

Recall is still namespaced per scraper identity, so one scraper's responses
never leak into another's — but everything feeds the same shared knowledge
for `ask()`.

## Memory depth

`memory` controls how far back the brain looks before deciding a request is
known:

| Depth      | Window  | Default | Use for                          |
| ---------- | ------- | ------- | --------------------------------- |
| `fresh`    | 1 hour  |         | prices, stock, anything volatile |
| `recent`   | 24 hours| ✅      | daily crawl cycles               |
| `standard` | 7 days  |         | listings, catalogs               |
| `deep`     | 30 days |         | slow-changing reference data     |

See [Memory Depth](/docs/sdk/memory-depth) for details.
